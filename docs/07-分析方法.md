# 07 · 分析方法

这份文档说明：数据怎么来的、怎么洗的、每个数字怎么算的、哪些地方不能比。想复核或改写就去 `scripts/`，指标定义与代码一一对应。

## 一、采集

### 为什么不是"抽样"而是"图遍历"

B站把搜索接口对本机 IP 封了（`x/web-interface/wbi/search/type` 与未签名版都返回 412 风控页，换 cookie/UA、等十分钟都不行；`newlist` 同样 412）。能匿名稳定拿到元数据且自带分区的只剩一个入口：

```
GET https://api.bilibili.com/x/web-interface/archive/related?bvid=<BV>
→ 40 条邻居，每条含 bvid / title / tname / tid / desc / pubdate / duration / owner / stat / cid
```

于是采集变成一个**图上的 BFS**：种子集合（榜单 + 存量搜索结果）→ 每个视频取 40 个邻居 → 新 bvid 入队 → 重复。邻居高度重叠，去重率稳定在 64%，42,161 次请求 / 103 分钟，最终 60 万条唯一稿件。

**这决定了样本性质**：它是"B站推荐图上一个连通片的广度优先覆盖"，不是全站均匀抽样。度高的分区（日常、影视剪辑、综合）自然多，冷门分区（电影、番剧资讯、动态漫）只有个位数。所以本文档里所有分区数字都只描述"这一片图内部"，不能当全站占比用。

### 文本侧

- 弹幕：`https://comment.bilibili.com/<cid>.xml`，XML 每条 `<d p="出现时间(秒),模式,字号,颜色,时间戳池,用户哈希,行号">正文</d>`。每视频按时间均匀抽，上限 2,000 条 → 30 万条来自 581 个视频。
- 评论：`x/v2/reply/wbi/main`，匿名状态下每视频只能拿约 32 条（顶楼 6 条 + 楼中楼首页）。2,180 个视频 → 70,269 条。
- 文本侧覆盖的 2,183 个视频与 60 万元数据不是同一批（文本侧另有 862 条孤儿），已用 `scripts/patch_missing_videos.py` 补了 1,015 个 bvid 的元数据。

### 其它平台

见 `DATA-SOURCES.md` 的入口表与实测天花板。抖音/快手/西瓜三家需签名参数，匿名拿不到，库里的 0 是**结果**，不是漏采。

## 二、清洗

`build_db.py` 的 `clean()`：

1. HTML 实体反转义（`&amp;` → `&`）→ 去标签（`<b>`、`<br>` 等）→ 连续空白压成一个空格。
2. 脱敏：手机号 `1[3-9]\d{9}` → `<手机号>`；邮箱 → `<邮箱>`；18 位身份证 → `<身份证>`；5–11 位 QQ 判定 → `<QQ>`。
3. 去重：`videos` 以 bvid 为主键；`texts` 以 `platform + kind + bvid + 文本 + 时间` 指纹去重；`video_tags` 以 `(bvid, tag)` 去重。
4. 数值归一：时长转秒、时间转 Unix 秒；`like` 是 SQL 保留字，列名作 `like_`。
5. **不做**的事：不改错别字、不做繁简转换、不删脏话、不补标点。语感分析要靠这些原始特征。

## 三、指标定义

### 文本形态（`docs/05` 与技能包里的数字）

| 指标 | 定义 | 为什么这么算 |
|---|---|---|
| `chars_median` | 文本长度中位数（Unicode 字符数，含标点） | 中位数比均值抗长尾；弹幕均值被少数长串拉高 |
| `short_le8` | 长度 ≤ 8 字的条目占比 | "短句"的可操作代理；弹幕的典型单位是一个气口 |
| `no_end_punct` | 全文**不含任何**句末标点的条目占比 | 判断"有没有按书面句子写"的最硬信号；真人聊天大多不结句 |
| `modal_per100` | 语气词出现次数 / 字数 × 100（`[啊吧呢呗嘛咯哦噢呀哈嘿嗯诶欸啦嘞]`） | 密度而非个数，长短文本才能比 |
| `laugh_rate` | 命中 `哈{2,}\|233+\|hhh+\|草{1,}\|笑死\|笑不活` 的条目占比 | 笑声标记是情绪强度的低成本代理 |
| `repeat_rate` | 命中 `(.)\1{2,}`（如"啊啊啊"、"哈哈哈哈"）的条目占比 | 叠字是口语化与情绪外溢的语法特征 |

句子切分用 `[。！？!?；;\n]+`，用于句长统计；**小句**按逗号/顿号/冒号再切一层，用于节奏（技能包用它的中位数）。

### 分区与热度（`docs/02`、`docs/04`）

- 每分区：条数 `n`、播放中位数、时长中位数、最早发布年份。
- 千播点赞 = `sum(like)/sum(view)*1000`（仅 view > 0）；万播评论 = `sum(reply)/sum(view)*10000`（仅 view > 0）。用总量比而非逐条均值，避免小播放量视频把均值炸掉。
- 时间分布按 `pubdate` 的小时 / 星期 / 年份分桶（北京时间）。

### 兴趣图谱（`docs/03`）

1. 边 = 同视频共现的标签对，权重 = 共现次数（`video_tags` 自连接）。
2. **标签传播（label propagation）**：初始每个标签自成一类；按标签出现频次从高到低遍历 6 轮，把标签改成"邻居权重和最大的社区标签"；无变化则提前停。
3. 输出：每个社区的规模、成员（按共现强度排序）、落点分区。
4. 已知偏差：标签只覆盖 46,980 个视频（7.8%），所以图反映的是"被富化过的那批视频"的兴趣结构；社区的粒度随边阈值变化，不要把它当唯一真值。

### 一致性核对

`scripts/check_db.py` 会打印：各表行数、FTS 行数、孤儿文本数、标签覆盖数、两个 engagement 比值、top/tail 分区、带文本的分区数。改完数据先跑它，再跑 `analyze.py`。

## 四、复现

```bash
python scripts/build_db.py          # raw/*.jsonl → db/video-corpus.sqlite（18 秒）
python scripts/analyze.py           # → db/stats-video.json
python scripts/gen_docs.py          # → docs/01..06（数字全从 stats 来，不手写）
python scripts/gen_skill.py         # → SKILL.md（同样不手写数字）
python scripts/check_db.py          # 一致性核对
```

**所有 md 里的表格都是脚本生成的**：改一个阈值重跑，文档跟着变，不会出现"文档说 6 字、库里 7 字"这种漂移。

## 五、不能做什么（统计上）

1. **不能当全站分布**：图遍历样本，分区占比失真。要全站比例必须拿到搜索或分区列表接口。
2. **不能做因果**：只有快照，没有时间序列（`pubdate` 是发布时刻，不是播放增长曲线）。
3. **不能跨平台比绝对量**：爱奇艺等播放量 null；B站播放量口径与其它平台不同。
4. **弹幕/评论形态不能外推到"用户平时怎么说话"**：它们是**对着视频说话**的语域，比私聊更表演化、比文章更碎。技能包里有"弹幕语域 / 评论语域"的区分，别混用。
5. **小样本分区不要引用**：`n < 300` 的分区在 `gen_docs.py` 里会被过滤（技能包用 `n >= 3000`），引用前先看 n。
