# 08 · 数据字典

库文件：`db/video-corpus.sqlite`（全量，Release 附件）、`db/sample.sqlite`（抽样，仓库内）。结构完全一致，DDL 见 `db/schema.sql`。

时间字段一律是 **Unix 秒（UTC 基准，北京时间解读）**，`*_ms` 是毫秒，`crawled_at` 是 ISO8601 带 `+08:00` 的字符串。

## videos — B站视频元数据（601,044 行）

| 列 | 类型 | 含义 | 备注 |
|---|---|---|---|
| `bvid` | TEXT PK | 稿件号，如 `BV1xx411c7mD` | 全库唯一 |
| `aid` | INT | 旧 av 号 | 部分来源缺失 |
| `title` | TEXT | 标题 | 已去 HTML 标签与实体 |
| `tname` | TEXT | 分区标签名 | 新老两套并存（`科学探索` / `科学·探索·自然`），按名统计会略多于按实体 |
| `tid` | INT | 分区 id | |
| `partition_path` | TEXT | 分区路径，如 `游戏/单机游戏` | 69.7% 有值 |
| `keyword` | TEXT | 采到它的关键词 | related 图扩展的条目为空 |
| `source` | TEXT | `related` / `search` / `newlist` / `ranking` / `popular` / `view_patch` | 决定哪些字段可能为空 |
| `author_mid` / `author_name` | INT / TEXT | UP 主 | 公开信息 |
| `pubdate` | INT | 发布时刻 | |
| `duration_s` | INT | 时长（秒） | |
| `desc_len` | INT | 简介字数 | **只存长度，不存原文** |
| `url` | TEXT | 稿件地址 | |
| `crawled_at` | TEXT | 抓取时刻 | |
| `view` / `danmaku` / `reply` / `favorite` | INT | 播放 / 弹幕 / 评论 / 收藏 | 公开计数快照 |
| `coin` / `share` | INT | 投币 / 分享 | `source='search'` 记录为 null（接口不返回） |
| `like_` | INT | 点赞 | `like` 是保留字故加下划线 |
| `cid` | INT | 弹幕分P id | 弹幕文件 `comment.bilibili.com/<cid>.xml` 用它 |

## video_tags — 视频-标签关系（442,598 行，46,980 个视频）

| 列 | 类型 | 含义 |
|---|---|---|
| `bvid` | TEXT | 外键到 `videos.bvid` |
| `tag` | TEXT | 标签原文 |

只有被"富化"过的那批视频有标签；主表 60 万里其余条目**未采标签**，不等于没有标签。

## texts — 弹幕与评论（370,269 行：弹幕 300,000 + 评论 70,269）

| 列 | 类型 | 适用 | 含义 |
|---|---|---|---|
| `id` | INT PK | 全部 | |
| `platform` | TEXT | 全部 | 目前恒为 `bilibili` |
| `kind` | TEXT | 全部 | `danmaku` / `reply` |
| `bvid` / `cid` / `aid` | TEXT/INT/INT | 全部 | 所属稿件 |
| `tname` | TEXT | 全部 | 冗余分区名，方便按分区聚合（免 join） |
| `text` | TEXT | 全部 | 原文（只做了四类脱敏） |
| `time_ms` | INT | danmaku | 在视频中出现的时间（毫秒） |
| `mode` / `color` | INT | danmaku | 弹幕模式（1 滚动 / 4 底部 / 5 顶部…）与颜色 RGB 十进制 |
| `rpid` | INT | reply | 评论 id |
| `root` | INT | reply | 楼层根评论 id |
| `parent` | INT | reply | 直接父评论 id（楼中楼） |
| `depth` | INT | reply | 楼层深度，顶楼为 0 |
| `likes` | INT | reply | 点赞数 |
| `ctime` | INT | reply | 评论时间 |
| `uid` | INT | reply | 作者 uid（已哈希化来源，仅本库内可比） |
| `video_pubdate` | INT | 全部 | 冗余的视频发布时刻 |
| `crawled_at` | TEXT | 全部 | 抓取时刻 |

> 注意：`texts` 里 862 条记录的 `bvid` 在 `videos` 中不存在（文本采到、元数据不可见），join 时用 `LEFT JOIN` 别用 `INNER JOIN`。

## other_videos — 其它平台（50,334 行）

| 列 | 类型 | 含义 |
|---|---|---|
| `platform` | TEXT | `iqiyi` / `youku` / `weibo` / `qqvideo` |
| `item_id` | TEXT | 平台内 id |
| `title` / `author` | TEXT | 标题 / 作者 |
| `category` / `interest` | TEXT | 平台给的频道/兴趣分类 |
| `publish_ts` / `duration_s` | INT | 发布时刻 / 时长 |
| `view` / `like_` / `comment` | INT | 公开计数；**爱奇艺三类恒为 null**（匿名接口不返回，是平台事实） |
| `url` / `source` / `crawled_at` | TEXT | 地址 / 采法 / 时刻 |

主键是 `(platform, item_id)` 复合键——不同平台的 id 会撞。

## regions — B站分区表（72 行）

| 列 | 类型 | 含义 |
|---|---|---|
| `rid` | INT PK | 分区 rid |
| `tname` / `tid` | TEXT / INT | 分区名与 tid |
| `sample_bvid` | TEXT | 探针用的样本稿件 |
| `source` | TEXT | 怎么得到的（`related` 反推 / 榜单 / 存量） |

分区树接口已废（`x/v2/region/index` 带签名也 `-400`），这张表是从样本稿件的 `tid/tname` 反推的，所以只有覆盖到的 72 个，不是全量分区。

## 全文索引

| 表 | 内容 | 用法 |
|---|---|---|
| `video_fts` | `title`, `author_name`（外部内容表，指向 `videos`） | `SELECT title FROM video_fts WHERE video_fts MATCH '原神';` |
| `text_fts` | `text`（外部内容表，指向 `texts`） | `SELECT bvid, text FROM text_fts WHERE text_fts MATCH '笑死' LIMIT 10;` |

FTS5 用 `unicode61` 分词，中文按字切——所以 `'原神'` 是两个字的邻接匹配，够用但不懂分词。要更准就上 jieba 建外部索引表。

## 常用查询片段

```sql
-- 每个分区的弹幕节奏（n≥300 才可信）
SELECT tname, COUNT(*) n, AVG(LENGTH(text)) avg_len, COUNT(*) FILTER (WHERE LENGTH(text)<=8)*1.0/COUNT(*) short_ratio
FROM texts WHERE kind='danmaku' GROUP BY tname HAVING n>=300 ORDER BY n DESC;

-- 某视频的弹幕时间轴（看情绪高峰落在哪）
SELECT time_ms/1000.0 s, text FROM texts WHERE bvid=? AND kind='danmaku' ORDER BY time_ms;

-- 楼中楼结构
SELECT depth, COUNT(*) FROM texts WHERE kind='reply' GROUP BY depth ORDER BY depth;

-- 播放-点赞散点（抽样库跑得动）
SELECT view, like_, tname FROM videos WHERE view BETWEEN 1000 AND 1000000;
```
